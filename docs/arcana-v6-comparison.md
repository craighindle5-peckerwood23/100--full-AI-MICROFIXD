## What happens when an operator asks a question

Arcana first classifies the text in the browser. A local handler can change a room, job, mission, or health record. A separate Express endpoint streams Gemini text and a structured summary. The summary carries follow-up questions, a suggested room, confidence, and complexity. The server measures elapsed time and first visible text, estimates tokens as one per four characters, and calculates throughput across the whole request. Confidence and complexity come from the model packet or fallback values. The UI labels the length of a display array as verified reasoning stages.

The supplied surface-code example illustrates the split. The word **codes** matches the sandbox handler's substring **code**. That handler queues a canned JavaScript sample, returns “Passed eBPF Inspection,” and links to the sandbox. The browser then fabricates completion after a timer. Neither the subject of the question nor the submitted scientific explanation establishes that a quantum simulation ran. Mission M-804 and job JOB-1102 are initial records.

Canonical chat enters the authenticated command router, applies Paragon preflight, retrieves scoped memory, calls the brain and records its output. Mission mode submits to the durable planner with authorized tools and approval handling. This supplies an implementation path for Arcana's links between answers and work. A link can identify the specific persisted mission, action, approval or artifact. A navigational suggestion is useful even when there is no action record.

## Transfer decisions

1. **Included in the PR.** Executive, Balanced and High-bandwidth answer styles feed fixed server-owned instructions into the existing brain. The tab reuses the canonical chat session and retrieval preferences. The cockpit displays reported provider, model, command time and stage names when available.
2. **Next cognitive-console candidate.** Stream the existing authenticated command's visible answer, support cancellation, and offer follow-up questions that retain the session. Verify partial output, late errors, and persisted completion before showing success. The experiment's Gemini route illustrates the interaction well; it would duplicate governance and memory if installed as another command entry point.
3. **Next execution candidate.** Connect result cards to durable mission, approval and sandbox records. A read-only question containing “code” is a regression case. Clicking a record should recover the same outcome after a reload.
4. **Next learning and healing candidate.** Combine Arcana's heuristic and recovery displays with provenance, a counterexample or failed probe, an approved change, and repeatable evaluation. Keep proposed improvements distinct from validated ones.
5. **Further presentation candidates.** Layer-filtered memory search, role-based agent cards, peer status with last acknowledgement, keyboard navigation, accessible voice controls and a lightweight avatar fallback. Each can use existing rooms and APIs.
